Webmail — fix External Mail Gmail connect: App Password with invisible Unicode spaces fails with `gmail_auth_failed`.

Workdir: /data/home/webmail-r3-codex (already synced from VM ~/workspace/aistockvn-webmail, sha-verified — VM is the standard. Do NOT re-sync from anywhere else.)

ROOT CAUSE (already proven, do NOT spend time re-investigating broadly):
- `worker/gmail.ts:348` strips App Password spaces with `.replace(/\s+/g, "")`.
- JavaScript `\s` does NOT match zero-width space U+200B (nor U+180E, U+2060, U+200C–U+200F).
- When the user copies the App Password from Google's page, the paste can contain invisible characters, e.g. 'abcd\u200Befgh ijkl\u00A0mnop' (19 chars) -> after `/\s+/g` still 17 chars (U+200B survives) -> Gmail rejects LOGIN -> `gmail_auth_failed`.
- Verified with node: after `/\s+/g` the string is 17 chars; after the OmniMail regex below it is exactly 16.

FIX — follow OmniMail exactly (reference implementation `gmailAppPasswordField`, already verified):
```ts
const APP_PASSWORD_SEPARATORS =
  /[\u0020\u00A0\u1680\u180E\u2000-\u200F\u202F\u205F\u2060\u3000\uFEFF]/g;
```
1. In `worker/gmail.ts`, function `connectGmailAccount` (~line 348): replace `.replace(/\s+/g, "")` with `.replace(APP_PASSWORD_SEPARATORS, "")` (define the constant next to the function, same regex as above, character for character).
2. Validate AFTER stripping: password must match `/^[\x21-\x7E]{16}$/`. If not, throw `GmailError(400, <new code or reuse invalid_input>)` with a clear human-readable message (English, UI is English), e.g.: "Enter the 16-character App Password Google generated (Google Account > Security > 2-Step Verification > App passwords), not your regular Gmail password." NOTE: OmniMail deliberately does NOT strip tab/newline/control chars — they fail this validation. That means the existing test in `worker/gmail.test.ts` ("strips all whitespace ...", ~line 708, which pastes a tab + trailing newline and expects success) must be UPDATED to the new behaviour: tab/newline in the pasted value now yields the clear 400 error, not a successful connect. Update that test, do not keep the old expectation.
